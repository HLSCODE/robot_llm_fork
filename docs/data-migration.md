# 数据版本与显式迁移

启动只加载、校验当前数据，不隐式升级。旧数据通过一条命令按已登记的版本步骤连续升级到最新版；数据版本与软件发布版本独立。

## 使用

先关闭运行中的程序，备份重要实验数据，然后预览：

```shell
uv run robot-init migrate-data --dry-run
```

预览会读取配置指定的数据目录，逐文件显示版本路径与错误，不连接设备，不修改用户数据，不创建备份。缺少目标时，动作以“待配置”状态完成迁移，不再要求提供映射文件；日志会列出迁移后需要补全的动作。

确认后可直接执行：

```shell
uv run robot-init migrate-data
```

程序内的基础动作列表会标记“待配置”。打开动作编辑框，明确选择机械臂和工具后保存，标记随之移除。工作流、草稿、技能中的动作参数是独立副本，不会因基础动作修改而自动同步，须分别补全；未补全时允许加载和编辑，但执行前会报错，不发送设备指令。

迁移只对无法确定的目标填入空值，并保存 `_pending_target_fields` 列表，不默认选择左/右臂。该标记只允许加载、编辑时豁免对应空目标，其他字段仍严格校验。不要手工删除标记来绕过编辑；正常保存会在目标补全后自动清除它。

### 可选：升级旧版本时批量指定目标

从 `config/migration-targets.example.json` 复制一份映射文件，按报告填写真实动作 ID（优先）或动作名称：

```json
{
  "actions": {
    "吸液": {"arm": "right", "tool_id": "pipette_1"},
    "某个旧夹爪动作的ID": {"arm": "left", "tool_id": "dh_rgd_gripper_1"}
  },
  "defaults": {}
}
```

映射只是确定动作语义，不要求该工具当前已配置、挂载或在线。技能步骤还可通过 `技能ID/步骤ID` 单独映射。动作 ID 优先于同名动作名称，建议使用稳定 ID 避免同名快照混淆。

若确认所有某类动作使用同一目标，也可明确设置 `defaults`，例如 `"defaults": {"吸液枪": {"arm": "right", "tool_id": "pipette_1"}}`。动作级映射优先于类别默认值；不会覆盖旧数据中已有的 arm/tool_id。系统不根据设备配置、动作名称或旧编号推测工具。

```shell
uv run robot-init migrate-data --target-map config/migration-targets.json --dry-run
uv run robot-init migrate-data --target-map config/migration-targets.json
```

映射文件不需加入 `config.toml` 的 include，不能作为 TOML 配置片段加载。交互初始化和 `--steps data_migration` 同样支持命令行 `--target-map`。

## 当前版本与支持范围

| 文档 | 当前版本 | 支持的升级 |
| --- | --- | --- |
| 动作库 `robot_llm.actions` | 4 | 旧列表记作v0；v0→v1→v2→v3→v4，已有v1/v2/v3从其版本继续 |
| 工作流 `robot_llm.workflow` | 6 | v5→v6，递归转换循环、子流程、并行分支中的动作快照 |
| 技能 `robot_llm.skill` | 3 | v1→v2→v3，补齐旧绑定字段并转换步骤参数 |

旧 `.task`、v1 `.workflow` 和草稿继续通过已有结构转换器生成规范工作流，再执行末端参数升级；不以空迁移器冒充未知工作流v2/v3/v4的格式兼容。遇到没有明确转换器的版本或未来版本，停止并报告，不强行改版本号。

动作库v1→v2规范化点位/marker，v2→v3补齐受支持的 Profile 信息，v3→v4转换末端参数。新版夹爪统一为“夹爪”执行器；旧“编号”被移除，不再参与路由，无法确定的 arm/tool_id 留空并标记待配置，原编号可在迁移备份中查看。未知参数、无法转换的点位等仍会报告，不能通过迁移绕过参数校验。

仅处理当前活动 Profile 及配置指定目录。未分 Profile 的旧机械臂数据只允许迁入原 `realman-rm75-dual`，不会把 RealMan 动作自动转成天机动作。已有目标文件不被旧副本覆盖。其他 Profile 需切换明确配置后分别迁移。

## 写入、备份与恢复

- 先转换并校验所有计划中的数据；有任意未解决问题，则不发布任何文件。
- 修改前检查源目标是否被改动，将被覆盖文件备份到 `data/migration-backups/versioned-data/upgrade-*/`；`manifest.json` 记录原路径和备份对应关系。
- 每个文件原子替换；普通写入异常或中断时尽力回滚已写文件，恢复原字节。回滚失败会保留备份并记录错误。
- **不是跨文件的操作系统级事务**：断电或进程被强制结束仍可能留下部分升级结果，可根据清单恢复；因此须关闭主程序后迁移，不与编辑/保存任务同时运行。
- 从备份恢复时：先关闭程序，将清单中非空 `backup` 对应文件复制回 `path`；`backup=null` 表示本次新建文件，应先核对再决定是否移走。恢复前保留现状副本，不盲目删除。
- 最新且合法的数据再次迁移不会改写。原地转换保持动作 ID、名称、工作流布局及其他元数据，不因工具离线删除动作。

缺失目录和动作库仍创建为空，不复制演示动作。旧 RealMan 轨迹只复制缺失目标，保留源文件；不会修改轨迹内容或转换为其他机械臂格式。
