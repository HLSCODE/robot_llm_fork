# 末端设备 Provider 抽象实施方案

> 文档类型：实施设计、接入说明与验收计划（代码已接入，待真机验收）  
> 设计日期：2026-10-22；实现更新：2026-10-26  
> 范围：双臂末端配置、夹爪与吸液枪 Provider、快换手状态、共享通信、入口统一与不兼容切换

## 1. 已确认的需求与边界

1. 左右机械臂可以分别配置末端安装方式，支持固定末端与快换末端组合，也支持两臂均安装夹爪。
2. 固定末端由配置确定工具实例；人工更换固定设备后修改配置并重启，不要求热切换配置。
3. 快换手只负责锁紧、解锁及自身状态查询，不识别、不记录当前安装的工具。
4. 工具是否安装正确由工作流的取放、移动和快换指令编排保证。
5. 执行到具体工具动作时，按动作声明的工具实例选择 Provider，发送该设备协议的指令。
6. 实际硬件中，工具通过快换手的通信触点接入系统；未安装时不能通过该链路响应。
   串口打开只代表通道可访问，不等于某把工具已在线。
7. 快换手与其后端工具使用同一串口时，必须共用一个物理连接，并统一调度收发。
8. 通信超时、响应校验失败或设备拒绝等情况，使当前动作失败，由既有执行策略处理后续流程。
9. 睿尔曼内置夹爪继续使用原 SDK、连接与控制语义；天机无需为了夹爪增加机械臂 SDK 接口。
10. 吸液枪、快换和现有换枪路径继续保留，不能因为统一夹爪接口而失去其他工具的操作能力。

本期不建设工具身份探测、工具位到工具的身份映射、当前安装工具注册表、自动选工具或自动换装。
不将“上次执行了某工具动作”推断为“现在仍装着该工具”，也不在通信失败后尝试其他 Provider。

## 3. 总体结构

```text
GUI / 工作流动作 / 视觉抓取 / 遥操作
                  │
                  ▼
        EndEffectorService（应用层）
     解析机械臂、工具实例、所需能力与资源
                  │
                  ▼
       Provider Registry / DeviceRuntime
         ├── RobotGripper ── 已有机械臂 SDK 连接
         ├── ZhixingGripperAdapter ─┐
         ├── ADPPipetteAdapter ─────┼── SharedConnectionManager
         └── ToolChangerAdapter ───┘      │
                                          ▼
                              命名串口连接、收发锁、超时控制
```

### 3.1 四个独立概念

| 概念 | 示例 | 职责 |
| --- | --- | --- |
| 工具类型 `kind` | `gripper`、`pipette` | 定义业务能力，不决定厂商协议 |
| Provider | `robot`、`zhixing`、`adp` | 实现能力并封装厂商差异 |
| 工具实例 `tool_id` | `robot_gripper_1`、`pipette_1` | 保存具体协议参数、连接引用及实例选项 |
| 机械臂末端配置 `mount` | `left` 固定，`right` 快换 | 描述可用工具范围、快换机构与通信通道 |

Provider 不是机械臂子类。工具实例是部署配置中的逻辑对象，不代表已安装或已连接。
同一种 Provider 可以创建多个实例；通信站号只是协议地址，不再隐含左右臂。

### 3.2 工具解析规则

- 固定末端：允许通过 `arm + capability` 解析配置中的固定工具；动作显式指定工具时必须与绑定一致。
- 快换末端：动作必须明确提供工具实例，；不读取“当前工具”。
- 检查目标臂是否允许使用该实例，以及工具是否具备所需能力；失败时在发送指令前报错。
- 快换路径中的工具连接必须与该臂配置的共享通道一致；SDK 内置能力允许使用其声明的 SDK 依赖。
- 同一工具类型有多个实例时，不能仅凭类型任选一个，也不能自动尝试所有 Provider。

例如“右臂、吸液枪 A、吸液 500 μL”解析为：

```text
arm=right + tool_id=pipette_1 + operation=absorb
  → 验证 right 的配置允许使用 pipette_1
  → 解析 pipette_1 的 ADP Provider 与 tool_bus_1 连接
  → 预留所需资源，执行协议交换
  → 校验响应，返回结果或类型明确的设备异常
```

## 4. 配置设计

默认采用主文件 + end-effectors/ 厂商子文件，均由根入口 include；主文件只设置刷新周期和左右臂挂载。
connections.toml 集中连接，robot.toml / zhixing.toml / adp.toml / kuaihuanshou.toml 分别声明工具。
以下为可直接写在入口的等价单文件示例；不要求把所有参数堆在主片段中。
示例以“左臂固定睿尔曼夹爪、右臂快换吸液枪或知行夹爪”为例。
连接参数只是结构示例，部署时必须依据设备协议核实。

```toml
[end_effectors.connections.tool_bus_1]
transport = "serial"
port = "/dev/hand"
baudrate = 115200
bytesize = 8
parity = "N"
stopbits = 1

[end_effectors.tools.robot_gripper_1]
kind = "gripper"
provider = "robot"

[end_effectors.tools.tool_changer_1]
kind = "tool_changer"
provider = "kuaihuanshou"
connection = "tool_bus_1"
response_timeout_seconds = 3.0

[end_effectors.tools.pipette_1]
kind = "pipette"
provider = "adp"
connection = "tool_bus_1"
response_timeout_seconds = 5.0
motion_timeout_seconds = 60.0
command_interval_seconds = 0.2

[end_effectors.tools.zhixing_gripper_1]
kind = "gripper"
provider = "zhixing"
connection = "tool_bus_1"
station = 1
response_timeout_seconds = 1.0
motion_timeout_seconds = 8.0

[end_effectors.mounts.left]
mode = "fixed"
tool = "robot_gripper_1"

[end_effectors.mounts.right]
mode = "exchangeable"
changer = "tool_changer_1"
tools = ["pipette_1", "zhixing_gripper_1"]
```

`mounts.right.tools` 是该臂可使用的工具配置目录，不是已安装设备清单，也不触发自动探测。
天机或其他机械臂使用外接固定夹爪时，只需把固定绑定指向对应外接工具实例。
两臂各有夹爪时，配置两个独立实例，通过挂载决定 SDK 臂或外接工具归属；同型号不等于同一实例。
未安装的臂显式设置 `mode = "none"`；不同子文件的工具按 ID 合并，仅实例 ID 相同时后定义替换前定义。

配置约束：

1. Provider、工具 ID、连接 ID 和能力必须有效；固定末端只能绑定配置允许的单个工具。
2. `robot` Provider 不指定机械臂厂商或臂编号，使用当前机械臂适配器能力；能力缺失只禁用该工具，不阻止启动。
3. 同一物理串口只能有一个连接所有者；不同名称指向同一端口时应拒绝冲突配置或显式合并引用。
4. 波特率、校验位等线路参数属于连接；响应超时和运动等待超时属于设备操作。
5. 共用连接的工具必须具备兼容的线路参数。本期不支持根据工具动作隐式切换串口波特率等设置。
6. 站号与左右臂解耦；同时访问同一连接、同一协议地址的重复实例必须检查冲突。
7. 保持现有 `config.toml` 单文件和 `include` 加载方式；可提供
   `config/fragments/end-effectors.example.toml`，新入口默认 include，仍允许在入口直接声明完整配置。
8. 示例文件提交版本库，实际配置按现有规则忽略；初始化命令增量复制新示例，不覆盖已有配置。
9. 动作与工作流继续遵守 Robot Profile 隔离，工具引用缺失必须明确报错，不能静默替换。

## 5. Provider 与能力接口

### 5.1 单个工具实例的小接口

工具实例接口不接受左右臂或总线站号，由路由和实例配置完成绑定。
应用服务仍接收 `arm`，用于校验部署关系和计算资源依赖。

| 能力 | 基本操作 | 可选操作与约束 |
| --- | --- | --- |
| 夹爪 | `open()`、`grip()` | 开合度定位、反馈、力度、停止，按设备实际支持声明 |
| 吸液枪 | 沿用吸液、注液、退枪头等现有能力 | 初始化、流速与容量限制保持现有语义 |
| 快换手 | `set_locked()`、`read_status()` | 供电控制与查询按硬件协议暴露，不包含工具身份 |

可选能力通过小 Protocol 或能力描述表达，不使用包含大量“未实现”方法的统一大接口。
Provider Registry 负责构造和能力声明，不负责决定执行哪一个工具。

### 5.2 夹爪语义

- `grip()` 保留厂商的夹持语义，不能一律实现为移动到行程终点；睿尔曼继续使用原力度夹持接口。
- 新的通用开合度采用明确命名的闭合比例：0% 为全开，100% 为全闭。
- 原始寄存器行程、方向反转、毫米与编码值的映射由 Provider 处理，不写入 GUI 或 Handler。
- 遥操作位置输入为 0～1000，在 Provider 明确转换或委托 SDK；
  映射方向需结合原协议及测试核对，不能把旧值直接当作新百分比。
- 无反馈能力时，不能显示伪造的实际开度或夹持成功检测；区分命令已确认与实际到位反馈。
- 各 Provider 声明真实停止能力。缺少停止能力不能通过空实现宣称支持，停止也不能默认张开夹爪。

### 5.3 睿尔曼连接复用

`RobotGripper` 引用当前机械臂适配器或其受控接口，复用连接、SDK 锁、力度、
速度、超时和已验证行为。适配器不再建立机械臂连接，不自行关闭共享 SDK 会话。
原机械臂对象继续拥有 SDK 生命周期；机械臂运动、轨迹、示教和工具架路径保持原入口。

## 6. 共享串口与资源仲裁

### 6.1 所有权与收发

由共享连接管理器按配置创建串口，每个物理通道只打开一次。Provider 获取借用接口，
其关闭操作只释放自身资源；应用宿主在停止所有使用者和后台查询后关闭物理连接。

快换手状态查询、吸液枪指令和夹爪指令共用事务锁。锁必须覆盖完整的一次请求与响应，
包含帧边界、响应校验与异常清理，避免相互读取或清空响应缓冲。
当前 `SerialTransport` 的实例锁不能解决两个独立实例打开同一端口的问题。

查询和业务操作均有等待上限；后台状态刷新不能绕过锁，也不能持续插队阻塞动作。
超时或半帧之后，先按协议恢复接收边界，再允许下一笔事务，防止迟到响应被当作新响应。
如果未来设备支持主动上报，应增加统一接收分发机制，不能让多个 Provider 并行读取串口。

### 6.2 执行资源

- 解析工具动作时同时解析臂、工具实例、共享连接以及必要 SDK 的资源依赖。
- 同一共享总线上的操作第一阶段保守串行；知行驱动现有整段运动互斥先保持不变。
- 不同连接上的左右工具能否并发，由实际 Provider 限制及现有执行策略共同决定。
- 睿尔曼夹爪第一阶段保留 `robot-system` 互斥要求，不借逻辑实例拆分放宽现有约束。
- 同一快换末端的锁紧、解锁、供电控制不能与工具动作并行；后续查询也不能与收发冲突。
- 工作流预检与实际提交必须使用同一个资源解析入口；禁止预检看旧设备 ID、执行却走新连接。
- 执行 Handler 使用运行时已经取得的资源；手动入口自行申请资源，避免同一命令重复申请导致自锁。
- 后台状态查询只进入共享连接的事务调度，不抢占整个任务的长时间资源租约。

“两个夹爪可分别寻址”“可并发运动”“可同步启动”是不同能力。没有厂商同步机制时，
不能把普通并行调度描述成同步启动。

## 7. 启动、执行与失败处理

### 7.1 启动

启动时解析配置、校验引用和注册工具实例。新配置下仅创建工具的逻辑端点，
固定外接工具也按需通信，不以注册成功表示物理在线；睿尔曼机械臂本身仍走既有启动检查。
未安装的快换工具不要求逐个初始化、握手或判在线，不能因为它们不响应而阻止整个程序启动。

快换手可独立检查状态；共享串口是否打开、快换手是否响应、某工具最近一次操作是否成功，
应分别展示。不得把静态注册状态长期当作某快换工具始终在线的证据。

### 7.2 工具动作

```text
读取动作的 arm / tool_id / operation / 参数
  → 校验臂绑定、工具能力和 Provider 参数
  → 解析并取得必要资源
  → 获取共享连接或已建立的 SDK 接口
  → 执行设备协议，等待并验证响应
  → 返回结果 / 设备异常，释放操作资源
```

如果设备需要复位、回零等可能改变硬件状态的初始化，提供明确初始化操作，
不在首次普通吸液、夹持动作之前偷偷执行。纯通信准备可以延迟到使用时完成。
初始化操作通过工具实例显式执行；不保留全局移液枪初始化入口。

快换手状态用于显示及显式动作结果，不用它推断工具身份。
本期不新增“已安装目标工具”前置条件；工具选择由流程编排保证。
原有资源互斥、动作控制策略及硬件错误处理仍然生效。

### 7.3 错误与重试

异常至少区分：配置/能力不匹配、连接打开失败、通信超时、帧或校验错误、设备拒绝、设备报警。
日志包含 `run_id`、动作 ID、逻辑臂、工具 ID、Provider、连接 ID、操作及原始错误码，
完整堆栈记录到文件，终端遵循现有日志策略。

工具动作异常必须进入现有步骤失败路径。串行流程不继续发送后续动作；并行流程沿用
既有失败取消策略，不承诺能够撤回其他分支已经发出的硬件指令。

吸液、注液等操作发生超时时，可能是“设备已执行但应答丢失”。禁止在通用层盲目重发。
只有 Provider 明确确认操作可安全重试，或能查询并消除结果歧义时才允许重试。
连接打开重试与设备动作重试分开配置；旧重试策略逐项审计，不能直接复制给所有新工具。

## 8. 快换手状态展示

| 字段 | 显示值 | 来源 |
| --- | --- | --- |
| 锁紧状态 | 锁紧 / 解锁 / 未知 | 实际状态查询 |
| 供电状态 | 开 / 关 / 未知 | 实际供电查询，协议支持时提供 |
| 通信状态 | 正常 / 超时 / 连接失败 | 最近查询或命令结果 |
| 更新时间 | 最近有效采样时间 | 运行时采样时间 |

命令写入成功或收到开关命令应答后可以显示“命令已确认”，但只有实际状态查询确认后
才更新为“已锁紧”等状态。查询失败或采样过期应显示未知/过期，保留最后采样时间供排查。
不显示“当前吸液枪”“已安装夹爪”等未经识别的信息。

状态查询在后台执行，使用低频、可配置、无积压的调度，且服从共享串口事务队列。
查询命令、校验和与响应含义先依据快换手协议核对，不能仅凭响应长度认定状态有效。

## 9. 统一入口与不兼容切换

- 仅使用 `[end_effectors]` 目录；旧 `[devices]` 末端字段直接报错，不读取、不迁移、不合成默认工具。
- 不再注册全局 `pipette`、`tool-changer` 或 `zhixing-grippers` 设备 ID；仅注册 `tool:<id>` 等明确资源。
- 固定末端通过明确的 arm 解析绑定；快换工具必须明确 tool_id，不从类型、站号或上次命令猜测当前设备。
- 通用夹爪动作使用 arm、tool_id、操作及闭合度，移除“知行夹爪”动作分类和“编号=左右臂”约定。
- SDK 原生接口和协议单位保持真实含义：夹持仍用夹持命令，遥操作 0 闭合、1000 张开不倒置；这不是旧配置兼容分支。
- GUI、手动控制、工作流、技能、视觉和遥操作统一路由，不保留厂商专用手动按钮和隐藏直连入口。
- 旧 Action/Workflow/实际配置不自动覆盖。使用者需要手动调整末端配置和动作参数，缺少目标时明确失败。

## 10. 建议模块落点

| 位置（拟新增或调整） | 职责 |
| --- | --- |

| `src/devices/robots/realman/` | 保留 SDK 连接与原夹爪实现，提供可复用受控接口 |
| `src/application/end_effectors.py` | 应用入口，解析目标、能力及资源依赖，组织手动操作 |
| `src/application/factory.py`、`src/devices/runtime/factory.py` | 组合依赖与注册实例，不在业务入口创建硬件连接 |

## 11. 分阶段实施

### 阶段一：配置与共享连接基础

- 新增配置模型、Provider 类型及工具/臂/连接引用校验。
- 实现共享串口所有权和借用机制，将快换手与 ADP 注入同一连接。
- 删除旧配置与回退路径，核对重复端口、波特率冲突、关闭顺序和事务超时恢复。
- 补齐快换手查询响应校验及上层状态接口，不启动身份探测。

完成标准：同一端口只打开一次；并发调用不串帧；任一 Provider 关闭不误关其他使用者。

### 阶段二：夹爪 Provider 与统一应用入口

- 接入睿尔曼薄适配器、知行外接适配器及模拟实现。
- 左右臂分别绑定实例，移除站号等于臂编号的内部假设。
- 手动控制与动作 Handler 接入统一解析，资源预检采用同一依赖描述。
- 保持睿尔曼夹持语义、SDK 数值语义及现有运动互斥，不增加第二份 SDK 会话。

完成标准：固定睿尔曼夹爪、固定外接夹爪、双臂不同夹爪均能通过同一应用入口控制。

### 阶段三：快换工具动作与入口覆盖

- 吸液枪和快换动作接入统一工具目录及共享通道，按动作明确选择 Provider。
- 快换工具按需通信，不在启动时强制初始化所有可选工具。
- 视觉抓取、遥操作、WebSocket、技能等所有入口全部接入统一路径。
- 核对从指定节点执行、循环、并行及取消时的工具参数与资源解析。

完成标准：未安装工具不影响启动；执行该工具动作无响应时明确失败，不改用其他 Provider。

### 阶段四：界面、迁移与交付

- 更新动作表单和左右末端状态展示，删除厂商专用 GUI 控制分支中的重复逻辑。
- 提供配置示例、增量初始化及必要的显式数据迁移，更新架构、配置与设备文档。
- 完成自动化测试和 Windows/Linux 真机验收，确认旧睿尔曼与换枪流程未退化。

每阶段交付可单独验证，不能在只完成基础设施时宣称所有调用方已经迁移。

## 12. 测试与验收清单

### 自动化测试

- 配置：固定/快换组合、双臂、不同 Provider、无效引用、重复端口及线路参数冲突。
- 连接：单次打开、共享收发、跨协议响应隔离、半帧与迟到响应、异常重连和最终关闭。
- 生命周期：一个实例失败不关闭其他使用者；后台查询停止后再关闭共享连接。
- 路由：按臂与工具 ID 选择实例；固定绑定不匹配、缺少能力或歧义输入在发送前失败。
- 夹爪：睿尔曼原 SDK 调用保持一致；知行站号可独立配置；开合方向和旧数值转换正确。
- 快换：锁紧/供电实际查询、未知状态、采样过期；不生成工具身份或安装记录。
- 执行：工具超时进入步骤失败，串行后续不执行；并行资源冲突在启动前拒绝。
- 重试：有副作用操作应答丢失时不盲目重发；连接重试不会触发动作重试。
- 启动：未安装的快换工具不响应时程序仍可进入主界面，设备初始化不暗中复位工具。
- 不兼容切换：旧字段、旧全局别名及旧编号动作被拒绝；SDK 原生能力、视觉和遥操作有回归覆盖。
- 数据：Robot Profile 隔离、配置初始化增量复制、迁移备份及不改写源工作流。

### 真机验收

| 场景 | 验收重点 |
| --- | --- |
| 睿尔曼原夹爪 | 原开关、力度夹持、位置及遥操作行为保持一致 |
| 天机 + 外接固定夹爪 | 无需天机 SDK 实现夹爪接口，逻辑臂与实例绑定准确 |
| 左右臂不同厂商夹爪 | 控制互不误路由，实际资源限制生效 |
| 快换手与 ADP 共用串口 | 状态刷新和吸注液不串包、不重复打开端口 |
| 工具未安装或触点断开 | 具体操作报超时/通信异常，程序不启动错误 Provider 或继续串行流程 |
| 不同工具在流程内切换 | 后续动作使用各自声明的 Provider，不执行身份轮询 |
| 中止、关闭与重新连接 | 无残留轮询线程、重复句柄或提前关闭共享 SDK/串口 |

自动化测试不能替代对串口协议、电气参数、开合方向、实际工具运动和停止行为的真机验收。

## 13. 实施前需核实的协议资料

1. 快换手状态、供电查询及操作应答的完整帧格式、校验规则与错误码。
2. 快换手和每种后端工具是否确实共用兼容线路参数，是否存在转发或上电等待要求。
3. ADP 的初始化、指令确认、动作完成和设备忙状态的真实语义，以及可否安全重试。
4. 知行夹爪可配置站号范围、方向和行程映射、运动结束条件及真实停止能力。
5. 各工具协议会不会产生主动上报或延迟回复，以决定是否需要统一接收分发。

这些核实服务于正确收发和执行结果判断，不扩大为工具身份识别项目。

## 14. 已落地接入与部署步骤

### 14.1 实现入口

- `configuration/end_effectors.py`：连接、实例和固定/快换挂载配置；校验重复端口、跨臂重复绑定和工具引用；SDK 能力缺失在工具层报告不可用。
- `devices/end_effectors/`：统一目标解析、四种 Provider 构造、睿尔曼连接复用与视觉组合门面。
- `devices/transports/shared_serial.py`：按物理端口单句柄、完整请求/响应互斥、逐请求超时、显式重连及引用释放。
- `application/end_effectors.py`：手动资源仲裁与快换手真实状态查询。
- `execution/end_effector_policy.py`、`handlers/end_effectors.py`：预检和执行使用同一工具依赖，复用既有执行引擎。
- 动作表单、设备面板、视觉抓取、转圈注液、放枪、手动控制、遥操作和 WebSocket 已接入工具选择。
- `gui/controllers/end_effector_status.py`：单后台工作线程低频查询，无排队积压；关闭先停止查询并等待退出，再关闭运行时。

### 14.2 如何启用

1. 执行 `uv run robot-config-init`，增量生成主片段及 `end-effectors/` 中的五个配置文件；已有配置不覆盖。
2. 主文件仅选择 `none/fixed/exchangeable` 和工具 ID。串口在 connections.toml 修改，站号、行程、超时在对应厂商文件修改。
   默认两臂 `none`。`robot` 实例无需随机械臂厂商切换；所选机械臂没有该能力时，工具不可用但程序仍可启动。
3. 在已有根入口 include 中加入主片段及 `end-effectors/connections.toml`、`robot.toml`、`zhixing.toml`、`adp.toml`、`kuaihuanshou.toml` 五个子文件。
   也可把完整 `[end_effectors.*]` 内容直接写入入口；新入口默认 include 此片段，不需要修改 schema_version=6；已有入口需手动添加。
4. 重启，在动作表单和设备手动控制中明确选择机械臂和工具实例。
5. 工具需要复位时，明确执行“吸液枪 → 初始化”；不会在普通吸液前隐式复位。

未配置 `[end_effectors]` 时不创建任何默认工具，工具动作明确失败。
不再启动旧知行独立驱动，不读取旧 ADP 配置；旧字段会在配置加载时拒绝。
旧动作不自动改写：请手动补全 arm/tool_id，删除夹爪编号字段，并改用通用夹爪动作。
新快换动作应填写 `arm` 和 `tool_id`；工具 ID 是部署引用，仍受 Robot Profile 隔离。

例如右臂吸液动作的业务参数：

```json
{"执行器": "吸液枪", "arm": "right", "tool_id": "pipette_1", "操作": "吸", "容量": 500}
```

通用夹爪“定位”使用 `闭合度`（0% 全开、100% 全闭）；旧睿尔曼位置仍是 0 闭合、1000 全开。
遥操作 `teleop_joint` 可选 `grip_tool_id`：单臂传字符串，双臂传 `{"左":"robot_gripper_1","右":"zhixing_gripper_1"}`；
原 `grip` 数值语义不变。切换工具 ID 后，即使位置相同也会向新实例发出指令。

### 14.3 边界与待真机确认

- 未挂载的实例只作为配置保存，不构造协议对象。`mode=none` 不进行设备操作；逻辑端点 READY 只表示配置和协议对象可用，不是已安装/在线证据；设备面板展示“配置”，不展示虚假的当前工具。
- 快换手状态默认每次完成查询后等待 2 秒再采样；失败显示未知并保留最后有效时间，超过 `max(10秒, 3×刷新周期)` 标记过期。
- 实际串口异常后保留一个响应超时的恢复静默窗口，下一次发送前清空旧缓冲；完整帧还由 Provider 校验地址、命令和校验和。
  这不是任意延迟/主动上报协议的统一分发器，不能保证隔离无限迟到的响应；有此类硬件行为必须补充协议与接收分发。
- 同一快换挂载内的互斥备选工具可以使用相同协议地址；固定工具和不同末端不能复用同一实例或同一协议地址。
- 不新增工具身份探测、位置映射、自动重发吸注液或假停止能力；关闭配置夹爪时不发送可能松开负载的失能指令。
- 快换手帧校验依据仓库现有请求帧结构补齐，仍需设备协议资料和现场返回帧核验；不能将模拟响应测试当作真机协议验收。
- 当前环境仅做模拟与协议替身测试，未连接真实机械臂、夹爪、快换手或移液枪；第 12 节 Windows/Linux 真机验收仍需执行。
