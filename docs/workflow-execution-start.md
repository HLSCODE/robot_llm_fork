# 从指定节点执行流程

在任务根画布单选一个节点，右键选择“从此节点执行”，或通过顶部“执行 →
从选中节点执行…”启动。确认框会显示起点名称、跳过的顶层节点数、剩余顶层节点数
和展开后的动作步骤数。取消确认不会提交执行，也不会改变画布状态。

普通“开始执行”按钮仍从完整流程开头执行。“从选中节点执行”的默认快捷键为
`Ctrl+Shift+Enter`，可以在快捷键设置中修改，使用时同样需要确认执行范围。

## 执行范围

| 起点 | 执行范围 |
| --- | --- |
| 顶层普通动作 | 该动作及后续所有顶层节点 |
| 顶层循环 | 从第 1 轮完整执行所有轮次，再执行后续节点 |
| 顶层子流程 | 完整执行子流程，再执行后续节点 |
| 顶层并行块 | 执行全部分支并汇合，再执行后续节点 |
| 循环体、子流程编辑页或并行分支内部节点 | 暂不支持；选择根画布上的外层节点 |

多选、未选中节点或已有任务执行时，该入口不可用。
画布保留完整流程，前置节点显示“已跳过”，其余节点按实际执行进度更新。
“已跳过”仅是本次运行的显示信息，不会写入流程数据；再次从头执行会清除该标记。

## 状态和前置条件

每次都是一次新的执行，不恢复上次运行的执行上下文，不自动执行被跳过的节点。
系统对剩余计划执行参数、Robot Profile、设备就绪和资源冲突等现有校验。
视觉补偿动作必须在本次计划中先获得对应工位、对应机械臂的视觉重定位结果；
如果重定位位于被跳过的部分、动作之后或同一并行块的其他分支，会在开始前拒绝执行。
完成并汇合的并行分支可以向后续动作提供重定位结果。

机械臂当前是否夹着物料、工具是否安装等物理前提不能由流程结构判断，
需要在确认执行范围时检查。暂停、恢复和停止继续使用既有执行控制。

## 实现

`WorkflowCompiler.compile(document, start_node_id=...)` 按稳定的顶层 `node_id`
生成临时剩余计划，保持完整容器结构和节点身份，不修改编辑文档。
`CompiledWorkflow.skipped_entries` 保存仅供画布显示的前置条目；剩余计划的
运行索引从 0 开始，进度事件通过节点和动作 UUID 映射回完整画布。
`workflow_start_dependencies.py` 检查本次运行的视觉状态前置依赖。

该入口目前用于 GUI 手动调试，不改变服务端和 AI 的默认全流程执行方式。
