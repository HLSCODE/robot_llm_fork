# 基于大模型动态反馈的自适应粉末精准取粉系统 — 项目综述

## 一、项目概述

> 文档状态：未立项概念方案，不代表当前代码或当前重构目标。当前生产实现是
> [确定性规则闭环加粉](powder_dispense_agent.md#当前实现边界)。2026-08-04
> 评审决定不在本轮引入四 Agent；满足专项文档中的重开条件后再独立立项。

本方案设想在原有加粉称重器基础上，引入大模型作为动态决策核心，通过 4 个协作
Agent 实现粉末取样的智能化与自动化。

### 核心目标

- **精度**：取粉误差控制在目标量的 ±5% 以内
- **泛化**：陌生粉末无需人工调参，自动探索并积累经验
- **效率**：已知粉末快速取粉，LLM 仅在关键环节介入
- **可解释**：每轮决策记录推理理由，参数变更可追溯

### 硬件平台

| 设备 | 型号/类型 | 通信方式 |
|------|-----------|----------|
| 步进电机 | B/M 系列（4个：加粉头、防风罩、电批旋转、电批升降） | RS-485 Modbus RTU |
| 电动夹爪 | EF 系列 | RS-485 |
| 敲击装置 | CIO300 | RS-485 |
| 电子天平 | XB/ES 系列 | 独立串口 |

## 三、多智能体系统

### 3.1 四个 Agent

| Agent | 中文名 | 职责 | 调用时机 |
|-------|--------|------|----------|
| CharacterizationAgent | 物性表征 | 分析 DOE 试探数据，评估粉末 k/eta/流动性 | 陌生粉末首次取粉 |
| RecipeArchitectAgent | 配方架构 | 生成多阶段加粉策略（粗加/精加/微调） | Phase 2 启用 |
| ValidationAgent | 闭环验证 | 评估取粉 KPI，判断是否达标 | 每次取粉完成 |
| OptimizationAgent | 配方调优 | 分析失败原因，建议参数修正 | 不达标时触发 |

### 3.2 AgentManager（调度中枢）

统一管理 4 个 Agent，提供 5 个对外接口：

```python
class AgentManager:
    def decide_next_steps(...) -> int          # 每轮步数决策（核心）
    def characterize_new_powder(...) -> dict   # 陌生粉末 DOE 分析
    def generate_recipe(...) -> dict           # 分段配方生成
    def validate_result(...) -> dict           # KPI 评估
    def optimize_recipe(...) -> dict | None    # 失败修正
```

关键属性：
- `last_reasoning`：最新一轮推理文本（显示在 GUI）
- `last_suggested_max_steps`：LLM 建议的最大步数（只增不减）
- `last_suggested_down_steps`：LLM 建议的电批下降步数
- `llm_available`：LLM 连接状态
- `total_llm_calls`：API 调用计数

### 3.3 DeepSeek API 客户端

```python
class DeepSeekClient:
    def chat(messages, temperature, response_format) -> dict
```

- OpenAI 兼容接口（`/v1/chat/completions`）
- JSON Mode（`response_format: {"type": "json_object"}`）
- 超时 300 秒（仅上限，响应早到早返回）
- HTTP 5xx/429/超时 → `LLMUnavailableError` → 暂停程序

## 四、完整取粉流程

### 4.1 状态机（9 个状态）

```
IDLE → ADD_CANISTER → READY_TO_ADD → ADDING → ADD_COMPLETE → EJECTING → IDLE
                         ↑_______________↓          ↓
                    STOPPING ← (cancel)    ERROR ← (exception)
                                               ↓
                                          RESETTING → IDLE
```

### 4.2 粉末匹配流程

```
用户选择/输入粉种名称
  │
  ├── powder_params/{name}.json 存在？
  │   ├── 是（已知粉末）
  │   │   ├── 第 1 轮：公式（target × k × initial_fraction）
  │   │   └── 第 2 轮起：LLM 逐轮决策
  │   │
  │   └── 否（陌生粉末）
  │       ├── DOE 摸底 5 轮（100→200→500→1000→2000 步）
  │       ├── LLM 分析 DOE 数据 → 生成初始 k/eta/flow_category
  │       ├── 保存 JSON → 进入观察期
  │       └── 观察期 2 轮有效数据后 → LLM 正常决策
  │
  └── 取粉完成 → 保存 step_effectiveness → 更新 JSON
```

### 4.3 物理动作序列

```
1. 放入空瓶 → 关防风罩 → 移动夹爪 → 天平去皮
2. 放入粉罐 → 夹爪夹取 → 下降加粉头 → 天平去皮
3. 选择粉种 + 目标量 → 下降电批 → 开始加粉
4. 每轮：LLM决策步数 → 6号电机旋转 → 敲击 → 等天平稳定 → 读数 → 循环
5. 达标 → 电批回撤 → 等尾料沉降 → 最终称重 → 保存记录
```

## 五、决策规则体系（优先级从高到低）

### 规则 1：有历史数据 → 渐进突破

**条件**：`step_effectiveness` 表中有数据（已知粉末）

- 连续 2 轮同一步数零落粉 → 步数 ×1.5~2 倍（变步长扰动）
- 同时增大 `suggested_down_steps`（每次 +5000）
- 步数增幅上限：<2mg 时最多到 500，2-5mg 时最多到分档上限
- **绝不跨数量级跳变**（100→50000 = 找死）

### 规则 1.5：效率驱动

- 如果 `剩余量 / 历史 avg_mg > 10 轮`，主动建议增大 `max_steps`
- 根据 `step_effectiveness` 表外推，数据驱动不盲猜

### 规则 2：新粉末观察期

**条件**：`step_effectiveness` 为空 + 有效落粉 < 2 轮

- 步数上限 = `max_steps × 0.2`
- 连续零落粉可逐步 ×2 增加，但不超过 `max_steps × 0.5`
- 收集 2 轮有效数据后自动解除

### 规则 3：正常分档限速

| 剩余量 | 步数规则 |
|--------|----------|
| > 5 mg | 直接用 max_steps |
| 2-5 mg | 步数上限 4000 |
| 1-2 mg | 步数上限 2000 |
| < 1 mg | 100-200 步微调 |

### 规则 4：安全公式（最低优先级）

仅当最近一轮有落粉时参考：
- 预估 = `k × steps`
- 最坏情况 = `k × steps + 2.5 × eta × √(k × steps)`
- 安全条件：`current + worst_case ≤ target`

## 六、粉末参数 JSON 结构

```json
{
  "k": 0.000135,
  "eta": 0.265,
  "flow_category": "低流动性",
  "max_steps_per_round": 50000,
  "min_steps": 100,
  "initial_fraction": 0.333,
  "screwdriver_down_steps": 86000,
  "step_effectiveness": {
    "200":   {"max_mg": 0.6, "min_mg": 0.1, "avg_mg": 0.3, "count": 6},
    "2000":  {"max_mg": 0.5, "min_mg": 0.1, "avg_mg": 0.3, "count": 4},
    "10000": {"max_mg": 1.5, "min_mg": 1.5, "avg_mg": 1.5, "count": 2},
    "50000": {"max_mg": 9.7, "min_mg": 4.0, "avg_mg": 6.7, "count": 14}
  },
  "tail_residue_history_mg": {}
}
```

### 字段说明

| 字段 | 类型 | 含义 | 来源 |
|------|------|------|------|
| `k` | float | 步数→毫克转换率 | DOE摸底 + 线性回归拟合 |
| `eta` | float | 噪声系数（越大越不稳定） | DOE摸底 + 残差加权 |
| `flow_category` | str | 流动性分类 | DOE摸底（LLM 分析） |
| `max_steps_per_round` | int | 单轮最大步数 | LLM 动态建议（只增不减） |
| `min_steps` | int | 单轮最小步数 | 默认 100 |
| `initial_fraction` | float | 首轮公式系数 | 默认 1/3 |
| `screwdriver_down_steps` | int | 电批下降深度 | 配置文件 + LLM 动态调整 |
| `step_effectiveness` | dict | 步数→落粉统计（max/min/avg/count） | 每次取粉累积（只记录 actual_mg>0 的轮次） |
| `tail_residue_history_mg` | dict | 尾料补偿表 | 手动校准 |

## 七、关键参数配置

### LLM 配置（device_control.toml）

```toml
[llm]
enabled = true
api_key = "sk-xxx"
model = "deepseek-v4-pro"
base_url = "https://api.deepseek.com/v1"
timeout_seconds = 300.0
```

### 取粉参数

```toml
[machine.powder_dispensing]
motor = "electric_screwdriver_rotation"   # 执行加粉的电机
step_sign = 1                              # 旋转方向
settle_seconds = 0.5                       # 电机停后等天平稳定
stable_attempts = 5                        # 连续稳定读数次数
tapping_enabled = true                     # 敲击装置
tapping_channel = 2                        # 敲击通道
tapping_frequency_hz = 5.0                 # 敲击频率
max_rounds = 20000                         # 单次最大轮次
```

### LLM 可动态调整的参数

| 参数 | LLM 输出字段 | 调整方式 |
|------|-------------|----------|
| 每轮步数 | `steps` | 逐轮决策 |
| 最大步数 | `suggested_max_steps` | 只增不减，自动更新 JSON |
| 电批下降深度 | `suggested_down_steps` | 自动更新 JSON |

## 十、关键设计决策与经验教训

### 已解决的问题

| # | 问题 | 解决方案 |
|---|------|----------|
| 1 | DOE 摸底返回 k=0 卡死 | 安全下限 k≥1e-6, eta≥0.01, max_steps≥2000 |
| 2 | 余量 >5mg 时暴力跳 max_steps 超调 | 新增分档限速：2-5mg→4000, 1-2mg→2000, <1mg→100-200 |
| 3 | 连续零落粉时 100→50000 步跳变 | 有历史数据时渐进突破（每次 ×2），不跨数量级 |
| 4 | 新粉 DOE 后直接 5 万步超调 10mg | 新粉末观察期：步数上限 = max×0.2 |
| 5 | suggested_max_steps 某轮不返回被清空 | 只增不减 |
| 6 | 100 步卡 15 轮不动，只加 down_steps | 连续 2 轮零落粉 → 步数 ×1.5~2 倍试 |
| 7 | 50000 步每次出 5mg 却从不建议增大 | 效率驱动：剩余/avg>10 轮 → 主动建议增大 |
| 8 | 累计重量因天平漂移倒退 | 累计值只增不减（monotonic） |
| 9 | 提前退出 0.5mg 阈值太粗 | 收紧到 0.2mg 且仅微调阶段启用 |
| 10 | 回撤后重量减少 | final_mg 不低于 pre_retract_mg |
| 11 | 粉种下拉框混入文件名 | 扫描 powder_params/ 目录，显示名=文件名 |
| 12 | Agent 日志最后几行丢失 | StreamHandler + buffering=1 行缓冲 |

### 已知局限

1. **LLM 推理延迟**：DeepSeek V4 Pro 每次 30-90s，制约取粉节拍
2. **无跨粉末泛化**：每种粉末知识独立，不共享
3. **新粉末首次慢**：DOE + 观察期 = 多次保守试探
4. **断网不可用**：无本地模型 fallback

### 后续优化方向

1. **决策表方案**：LLM 一次性生成查表，粗加阶段零延迟
2. **跨粉末泛化**：相似粉末参数迁移
3. **快/慢模型两级**：快模型日常决策 + 慢模型复杂分析
